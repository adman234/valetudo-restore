Robot connection

The key must be a private key file readable by the container. Key-only auth is used; passwords are never accepted or stored.

Backups

Schedule the backup before the robot's own nightly reboot (03:00–05:00 on Dreame firmware), so a wipe during that reboot is captured with fresh data.

Monitoring

Confirm samples is how many consecutive identical readings are required before acting. A single sample is noisy — wifi roaming and reboots both look like an outage for one poll.

Recovery

Auto-restore writes to the robot. It only ever triggers on a confirmed state where SSH succeeded and the binary was observed missing — never on an unreachable robot.

What a restore puts back

Vendor settings live in /data/config/ava and were previously skipped, which is why things like obstacle images and pet avoidance came back at factory defaults after a restore. A curated list is restored — never /data/config/miio (wifi and device identity) and never the history databases.

Rebuild references

Valetudo installs a voice pack from a URL + hash and stores neither on the robot, so these cannot be recovered from a backup. Record them here so a rebuild does not depend on remembering. The pack files themselves are backed up — these are the fallback. Same for duststreamer: if a backup has no copy, it is downloaded from this URL during a restore. It already points at Hypfer/Duststreamer — only an aarch64 build is published, which is what this robot runs, so you should not need to change it.
